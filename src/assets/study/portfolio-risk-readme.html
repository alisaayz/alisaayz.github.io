Personal Portfolio Risk Platform

Status: Personal portfolio analysis, risk-preference guidance, model development, and a local comprehension pilot workflow are implemented. Participant evaluation and final model testing remain planned. Last updated: November 4, 2026.

1. Executive summary

The Personal Portfolio Risk Platform is a financial analytics project for evaluating existing investments and comparing hypothetical portfolios. Its local application starts with one portfolio, explains historical risk, and offers an optional alternative comparison. A short preference guide separates self-reported comfort with fluctuations from cash-access needs and puts historical drawdowns in context. U.S. symbol discovery and on-demand application histories are separate from the fixed research dataset. A local study workflow prepares an evaluation of whether a chart helps readers interpret a portfolio risk report. A later suggestion layer will propose weight changes or replacement criteria relative to user-defined risk preferences, with optional candidate screening.

The central research question is whether a trained model can forecast volatility over the next 20 trading days more accurately than historical estimates. The implemented foundation downloads and audits real market history, preserves evidence, and loads versioned observations into DuckDB and Parquet. SQL views enforce source-selection rules and calculate calendar-aligned returns and historical volatility inputs. A separate versioned modeling layer builds causal features and pre-2026 targets under the chronological evaluation contract. The baseline report compares dated portfolios using historical covariance, volatility, drawdown, and holding risk contributions. Historical benchmarks and pooled gradient-boosted models are evaluated on development years; a local application now provides historical portfolio analysis with optional comparison; final model testing remains reserved.

Historical portfolio risk methodology

The demonstration report compares the allocations in demo_portfolios.json. SQL computes weighted daily returns and sample covariance; NumPy independently reconciles both. Covariance uses the most recent 252 common returns, denominator N−1, and annualization by 252. Portfolio volatility is sqrt(wᵀΣw). Euler contributions allocate that volatility to holdings and sum to the total; negative contributions are preserved.

In the equity-heavy demonstration, AAPL represents 30% of capital but 52.91% of estimated volatility risk. Capital weights alone do not explain portfolio risk. This is an instrument-level result; it does not measure underlying ETF holdings overlap.

Drawdown uses all common closing history, including initial capital. Both portfolios assume fixed weights rebalanced daily; today's allocation is replayed retrospectively. Risk estimates and drawdowns therefore cover different periods and are historical measurements rather than forecasts. The demeaned sample-covariance estimator is distinct from the existing squared-return/RMS historical input and implemented development forward-variance target.

Trained-model development and application boundaries

Each modeling row represents an instrument at a forecast date, with price inputs through that day's close. The implemented development target is realized variance over the following 20 trading sessions, annualized using a 252-session convention. Displayed volatility is the square root of variance; final-test numerical targets remain withheld.

Training, validation, and final testing follow the declared 2020–2024 / 2025 / 2026 chronological contract, with earlier development folds. Training labels whose future windows reach the next evaluation period are excluded. The implemented benchmark report evaluates trailing and exponentially weighted variance forecasts using annualized-volatility mean absolute error and variance QLIKE. Trained candidates use the same development origins and benchmark definitions. Final model scores remain unopened until the complete modeling recipe is frozen.

The local application supports daily, USD-denominated instruments in long-only, unleveraged portfolios. Fixed-weight historical scenarios explicitly assume daily rebalancing and represent hypothetical exposures rather than actual past investment performance. Portfolio forecasting will require a separate correlation estimate and separate evaluation. ETF look-through holdings, taxes, derivatives, and automated trading are outside the initial scope.

Later phase: explainable portfolio adjustments

If a portfolio exceeds the user's chosen risk tolerance, the planned suggestion layer will first explore changes to existing holding weights. It can later describe replacement characteristics or screen a defined candidate universe. Alternatives will show before/after estimated risk, concentration, risk contributions, allocation changes, and assumptions. If the requested target is infeasible, the system will report that result explicitly. Lower standalone volatility alone is insufficient; the candidate's co-movement with the remaining portfolio matters.

The adjustment roadmap defines proposed inputs, stages, visual workflow, and evaluation requirements. This is a later extension after the core risk system is validated. It provides options for the user to consider; it does not guarantee future risk limits, forecast returns, or execute trades.
